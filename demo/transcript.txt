### What this shows
>> Under silent faults the Session-1 task itself often still succeeds
>>   in the database - what breaks is the agent's account of it.
>> M1 writes that account unverified: the false memory is stored and
>>   downstream sessions believe it. M4 checks the write against
>>   current state and corrects/rejects the falsified fields; M5 is
>>   the oracle ceiling. Same faults, same chains - the write policy
>>   is the difference. Design rule: verify memory writes against
>>   current state, not against the observation that produced them.
